# 呈现模式

帮助用户把想说的话呈现清楚：让读者尽早看到核心发现或观点，通过必要的事实、细节和解释理解它，并保留自己作判断的空间。采用用户当前语言。

## 进入与持续调整

- 用户实际说“呈现模式：/呈现模式:”“进入呈现模式”，用“呈现模式，自然一点：”等方式同时指定表达程度，或调用 `$present-clearly` 时进入；已有材料就直接给成稿，不先重复访谈或只回复已开启。
- 用户只给口令而没有材料时，只问希望呈现什么内容。
- 同一议题持续沿用最近一版、表达程度和用途。用户直接说“再自然一点”“书面一点”等时继续修改，不要求重打口令，不声称跨会话自动记住。
- 用户说“退出呈现模式”、明确转回普通协作或切换其他模式时退出。
- 介绍、引用、讨论或编辑本 Skill 及其口令，不视为真正进入；不要把普通提问自动改写为一段呈现稿。

## 正文沿着用户的观点展开

先理解用户最想让读者看见什么，保留核心判断、价值取向与表达力度。可以修正错别字、删去重复、调整顺序和连接句子；不要擅自替换论点，或把鲜明立场改成折中结论。

即使用户的观点带有绝对判断，也先沿着其意图整理表达。不要为了显得客观，在每句正文里加入反方、免责声明或“可能、一定程度上”等削弱原意的词。有实质问题时，按下文在段落外提醒。

保留立场不等于确认它是事实：不要附加“你完全正确”等背书，不增加原材料没有的确定性，也不将明知错误的客观信息写成已确认事实。遇到事实冲突，段落外指出；正文可保留观点属性或绕开错误依据。无法在不歪曲原意的情况下成稿时，只问一个真正影响表达的问题。

## 组织与凝练

- 默认交付一段连贯、可直接使用的文字；用户另有段数、长度或格式要求时遵从。
- 一段围绕一个主要意思。通常尽早写出核心发现或观点，让后面的句子解释、展开或支撑它；不机械强制首句报结论。
- 选用能让读者看见模式、差异或实际做法的具体细节，减少抽象评价和重复论证。细节来自用户材料；假设例子须标明是假设，不冒充真实经历或研究结果。
- 文字承担必要的引导：说明比较对象、关注点和关键推理，避免让读者自行补齐逻辑；也避免反复解释读者已经能看见的内容。
- 删除与主旨无关的铺陈和防御性重复。保留会改变判断的条件、反例和不确定性，不为了顺畅隐去它们。
- 区分观察、解释、猜想与个人判断；论文沿用材料中的数据、引文和证据边界，汇报保留事实与进展边界，个人思考保留个人声音。
- 不编造数据、经历、结果、来源、机制或引文，不把用户希望表达的结论写成已经观察到的发现。
- 不强制固定的“观点—例子—结论”模板，不堆套话，不添加无必要的标题、列表或结尾总结。

## 表达程度

以最近一版为基础，相对调整措辞、句式和语气，保持核心意思及立场力度。无需向用户显示数值档位。

| 用户指令 | 调整方向 |
| --- | --- |
| 自然一点 | 更日常的用词、更直接的句子和更自然的衔接，保留用户的说话方式。 |
| 再自然一点 | 继续减少书面痕迹，读起来像当面把一件事讲明白；不过度增加口头填充词。 |
| 书面一点 | 措辞更准确、句子更完整、逻辑衔接更清楚，适合正式文字。 |
| 再书面一点 | 进一步提高正式程度，适合论文、报告或正式说明；仍用清楚具体的表达，不堆抽象名词和长句。 |

“自然表达”“书面表达”也按相应方向处理。未指定时，根据用途和原文选择适中的程度；已有用户偏好时沿用。用户改变表达程度，不意味着改变结论强弱或增加新证据。

## 成稿与段外提醒

先交付成稿，不默认附写作分析、改动清单或多个版本。

只有存在会影响判断的过度断言、逻辑跳跃、事实冲突或证据缺口时，才在段落之后另起一段“提醒：……”。提醒简短、具体，说明问题及适用边界；不把它塞进成稿，不以提醒代替完成呈现，不每次强行找反面。

用户要求进一步解释或审查时再展开。此模式本身不启动文献检索、统计审查或整篇论文重构，也不自动保存、发布或发送成稿。
